# Emin Kocan

Software engineer in Serbia, five years in. One problem keeps showing up in my work: how changes get reviewed, and how long that takes.

### How I got here

I started at Piton while still studying in Turkey, building live maps for city operators. At CentarNIT I built a design-review platform that took 15 designers at the Karlsruhe Institute of Technology from hours-long review loops to minutes.

On OpenStreetMap, review happens in public. I learned to write the RFC before the code and to split big work into reviewable pieces, which turned into [15 merged PRs](https://github.com/openstreetmap/openstreetmap-website/pulls?q=is%3Apr+author%3Akcne+is%3Amerged).

At Microsoft (through Hi-Tech Talents), I built the integration framework for a data-protection admin portal used by 200+ enterprise customers, and got into the habit of having Copilot review my changes before every PR.

### What I'm building

That habit raised a bigger question: what does my day look like when several agents write code at once and I review it?

**Patchbay** is my answer. It's a macOS app, written in Rust, that runs coding agents in parallel, each in its own git worktree, and only pulls you in when one needs a decision. Open source soon.

I also built and run **[SURP](https://github.com/kcne/surp)**, a transport booking platform live at [surp.rs](https://surp.rs).

If you're working on how people and agents build software together, I'd like to hear from you.
