# Emin Kocan

Software engineer in Serbia, five years in. One problem keeps showing up in my work: how changes get reviewed, and how long that takes.

### How I got here

I started at Piton while still studying in Eskişehir, Turkey. I built live maps for city operators and tooling for Kocaeli's rail and tram network.

At CentarNIT I built a design-review platform for 15 designers at the Karlsruhe Institute of Technology. Their review loop went from hours to minutes.

On OpenStreetMap, review happens in public, with maintainers who don't owe you anything. I learned to write the RFC before the code and to split big work into reviewable pieces, which turned into [15 merged PRs](https://github.com/openstreetmap/openstreetmap-website/pulls?q=is%3Apr+author%3Akcne+is%3Amerged).

At Microsoft (through Hi-Tech Talents), I built the integration framework for a data-protection admin portal used by 200+ enterprise customers. I also started having Copilot review my changes before every PR. It kept catching real bugs.

### What I'm building

That habit raised a bigger question. If agents write the code and I review it, what does my day look like when several of them are running at once?

**Patchbay** is my answer. It's a macOS app that runs coding agents in parallel, each in its own git worktree, following a workflow you design as a graph. It only pulls you in when an agent needs a decision. It's written in Rust and will be open source soon.
